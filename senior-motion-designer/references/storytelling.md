# Visual Storytelling

## Semantic beats

A beat is a change in meaning, not a sentence boundary.

Common beat roles:
- hook,
- premise,
- problem,
- escalation,
- contrast,
- reveal,
- mechanism,
- benefit,
- proof,
- transformation,
- resolution,
- CTA.

Two sentences can belong to one beat.
One sentence can contain several beats.

## Show relationships

Whenever possible, show relationships instead of isolated objects.

Better:
- one object blocks another -> problem,
- a fragmented system consolidates -> simplification,
- clutter collapses into a clean path -> efficiency,
- one node influences many -> distribution,
- distance shrinks -> speed,
- data flows into a decision -> intelligence.

Weaker:
- display an icon representing each noun.

## Literal vs conceptual

Literal visualization is useful when showing:
- product UI,
- physical action,
- exact process,
- recognizable feature,
- important object.

Conceptual visualization is useful when showing:
- uncertainty,
- complexity,
- scale,
- speed,
- conversion,
- growth,
- friction,
- attention,
- connection,
- transformation.

Mix both to avoid a video that is either too abstract or too literal.

## Setup and payoff

Strong motion design often creates anticipation:
1. establish a visual rule,
2. create an expectation,
3. alter or complete the rule,
4. reveal meaning.

Do not reveal every answer immediately.

## Visual callbacks

Reuse an object, motif, shape, or spatial relationship later in the video when it strengthens cohesion.

Callbacks are stronger than introducing a new visual language for every line.

## CTA

The final CTA should feel like the resolution of the video, not a separate template pasted at the end.

Where possible, transform an existing visual element into:
- logo,
- product,
- URL,
- button,
- final statement.

Give the final message sufficient hold time.
